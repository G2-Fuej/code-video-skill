# Interview playbook · 一次一题怎么问

这份文档给 `code-video` 的访谈阶段用。核心约束来自 grillme 模式：**一个问题、两三个具体选项、推荐项放前面**。

## 为什么一次只问一个

宣传片的每个决策都会影响后面好几个选择：片长决定节拍数，节拍数决定能用几种风格，受众决定语言风格，必须传达的一句话决定收尾画面。一次问三个问题，用户会挑最容易的那个答，剩下的变成默认值——而默认值往往是错的。

逐个问还有个副作用：用户在第 4 题的回答经常推翻第 2 题的假设。一次一题给这个机会。

## 提问模板

每个问题都按这个结构写：

```text
<一句话说清在问什么>

1. <推荐项> —— 推荐，因为 <一句话理由>
2. <备选项>
3. <备选项>
```

例：

```text
这个视频主要投在哪里？

1. B 站 / YouTube 横屏 16:9 —— 推荐，61 秒的信息密度够撑住横屏
2. 抖音 / 视频号竖屏 9:16 —— 需要重排所有排版，片长也该压到 30 秒
3. 官网首屏自动播放 —— 建议再压到 20 秒以内，无音轨
```

## 八个高影响问题（按依赖顺序）

### 1. 投放场景与片长

先问这个，因为它决定了后面一切。61 秒 / 19 幕是横屏宣传片的舒适区；竖屏需要重做排版；首屏循环要无音轨、更短。

**要拿到**：`duration`、`width/height`、`fps`、是否需要音轨。

### 2. 受众

开发者、玩家、投资人或大众。同一件事对不同人说不同话：

- 开发者：关心源码、架构、许可、可审计
- 玩家：关心能不能一键装好、有没有病毒
- 投资人：关心差异化和增长

**要拿到**：`kicker` 的语气、术语密度、是否要 `blueprint` / `editorial` 这两拍。

### 3. 只记一句话

「如果观众看完只记住一句话，是哪句？」

这句话最后落在 MATRIX 那一幕的 `payoff` 字段——代码雨汇聚成的那个短词。它必须短（≤4 字符或一个短单词），因为它要被字形覆盖。

**要拿到**：`beats[payoff].payoff`。

### 4. 叙事弧

三个子问题，但一次问一个：

- 项目要解决什么问题？（→ `flow`，画面是撞墙的粒子）
- 它怎么解决？（→ `voronoi`，碎片重组）
- 和同类比最不同的点？（→ `kaleidoscope` 或 `metaballs`）

**要拿到**：problem / repair / differentiator 三个节拍。

### 5. 硬事实清单

这一步必须严谨。宣传片里出现一个假数字，整个项目的可信度就没了。

要问：版本号、关键数据（行数、用户数、性能提升）、必须提及的第三方名字、仓库地址。

**要拿到**：`data.*`、`beats[blueprint].modules`、`beats[terrain].heights`、片尾署名。

### 6. 配色

有 VI 就用 VI。没有的话问一句项目气质：

- 工具/工程 → 冷蓝 + 青（默认）
- 创意/社区 → 暖橙 + 洋红
- 安全/审计 → 深底 + 高对比红

**要拿到**：`palette.*`。

### 7. 片尾卡

片尾卡是唯一会被暂停截图的画面，信息必须齐：

- 签名行（"written, rendered and scored in code" 这类）
- 项目名
- 仓库地址（要能看清，能打字）
- 上游署名（如果是 fork 或二次创作，这是法律要求）

**要拿到**：`endcard_lines`、`endcard.*`、`credits`。

### 8. 上传

仓库名、public / private、是否附带视频文件。

**要拿到**：`--repo`、`--private`。

## 什么时候停

满足任一条件就停止提问，直接开跑：

- 8 个问题问完
- 用户说「你定」「按推荐」「直接跑」
- 你已经能写出完整的 `beats` 且没有字段需要猜

反过来，如果某题的答案会让已经问过的题失效（比如用户突然说要竖屏），回去重问那一题，不要硬套。

## 常见用户类型与捷径

| 用户说 | 实际需要 | 可以跳过 |
|--------|----------|----------|
| 「给我的开源项目做个宣传片」 | 标准流程 | 第 1、2 题可合并成默认值 |
| 「我要投 B 站」 | 横屏 61 秒 | 第 1 题 |
| 「就照你上次那个做」 | 复用上一条 brief | 全部，改名字即可 |
| 「竖屏，30 秒」 | 重排 | 第 1 题必问，第 4-6 题需要适配 |
| 「随便，好看就行」 | 用默认值 | 全部，直接跑 |

## 收尾：结构化确认

问完后，用一段话把结论复述给用户，再开始跑：

```text
确认一下：61 秒横屏 1080p60，19 种视觉风格，主题是 <一句话>。
必须传达：<三个要点>。片尾署名 <上游作者>，仓库 <url>。
配色 <主色>。配乐程序合成，无采样。
现在开始渲染，约 25-40 分钟。
```

用户确认（或没反对）就开跑。这一步不能省——渲染很慢，改一次成本很高。
